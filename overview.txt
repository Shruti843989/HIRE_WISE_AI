🧠 Big Picture: Ye MLOps Module Karta Kya Hai?

HireWise AI me hum Resume Inflation Detector banaye hain.

Problem: Candidate ne resume me likha "Rating 9.5 out of 10 in Python" (claimed_skill). Lekin AI mock interview me uska score aaya sirf 4.0 (measured_ability).
Goal: Model automatically predict karega ki candidate ne resume exaggerated/jhooth bola hai (is_inflated = 1) ya genuine hai (is_inflated = 0).

Iske liye 4 main code files hain:

mlops/train.py — Model training aur MLflow experiment tracking.

mlops/monitor_and_retrain.py — Quality Monitoring, Retraining aur Quality Gate (Practical Tasks A–E).
1. mlops/train.py (Model Training & MLflow Logging)

Step 1: Data Generate Karna (generate_sample_data)
python
def generate_sample_data(num_samples=1000, random_state=42):
    claimed = np.round(np.random.uniform(2.0, 10.0, num_samples), 2)
    measured = np.round(np.random.uniform(1.0, 9.5, num_samples), 2)
    diff = np.round(claimed - measured, 2)
    labels = (diff > 2.0).astype(int)
    # 6% label noise
    noise_indices = np.random.choice(num_samples, size=int(0.06 * num_samples), replace=False)
    labels[noise_indices] = 1 - labels[noise_indices]
Kya ho raha hai: 1000 candidates ka synthetic data banta hai.
Rule: Agar diff (Claimed - Measured) 2.0 se zyada hai, toh label 1 (Inflated) hoga.
6% Noise kyu daali? Real life me human judgment 100% perfect nahi hoti. Agar noise na daalein toh model artificial 100% accuracy dikhayega jo real life me impossible hai. 6% noise se realistic 92-94% accuracy aati hai.

Step 3: Lifespan Context Manager (Production Best Practice)
python
@asynccontextmanager
async def lifespan(app_instance: FastAPI):
    app_instance.state.model = model_loader()  # Startup par ek baar load hota hai RAM me
    yield
Har request par bar-bar disk se model load karne se server slow ho jata hai. Lifespan se model server start hote hi RAM me load hota hai aur fast predictions deta hai.
Step 4: Prediction Endpoint (/predict)
python
@app.post("/predict", response_model=PredictResponse)
def predict(request: PredictRequest):
    diff = round(request.claimed_skill - request.measured_ability, 2)
    features = [[request.claimed_skill, request.measured_ability, diff]]
    prediction = app.state.model.predict(features)[0]
    return PredictResponse(inflated=bool(prediction == 1), difference=diff)
Difference nikalta hai, model ko feature vector deta hai, aur JSON response return karta hai: {"inflated": true, "difference": 5.5}.

📚 Part 2: Jo Topics Aapko Padhne Chahiye (Core Syllabus)

Yeh 7 core topics hain jo MLOps assessment aur interviews me 100% puche jaate hain:

Topic 1: Experiment Tracking vs Model Registry (MLflow)

Examiner ka favorite question: "Experiment Tracking aur Model Registry me kya farak hai?"

Experiment Tracking:
Har training attempt (run) ki history record karna.
Isme hyperparameters (n_estimators, max_depth), evaluation metrics (accuracy, f1_score), aur trained weights save hote hain.
Example: Agar aapne 10 alag-alag model train kiye, toh MLflow me 10 runs dikhengi.
Model Registry:
Centralized model hub jahan sirf best/approved models store hote hain.
Isme model versioning (v1, v2, v3) aur Aliases (champion, challenger) hote hain.
Production server direct Model Registry se @champion model fetch karta hai.
Topic 2: Data Drift, Concept Drift aur Performance Drift

Examiner ka question: "Task B me purane champion model ka F1-score kyu gir gaya?"

Data Drift:
Input features ka distribution badal jana (jaise pehle candidates average 5-6 rating claim karte the, ab naye batch me sab 9-10 claim karne lage).
Concept Drift:
Input aur target ka relation badal jana (jaise interview scoring criteria pehle se strict ho gaya, toh pehle jo gap genuine tha, ab wo inflated maana jane laga).
Performance Drift:
Drift ki wajah se deployed model ki accuracy/F1-score gir jana.
Solution: Jo humne kiya — naya data validate karke model ko Automated Retrain karna.

Topic 5: Real-time Model Serving (FastAPI Architecture)

Examiner ka question: "serve.py me Lifespan context manager ka kya role hai?"

Without Lifespan: Har HTTP request aane par disk se model load hota, jisse prediction me 2-3 second ka latency aata.
With Lifespan: Server start hote hi model memory (RAM) me ek baar load ho jata hai. Ab har prediction sirf 2 to 5 milliseconds me execute hoti hai.
Pydantic Validation: Type safety ensure karta hai. Agar koi claimed_skill: "nine" ya -5 bheje toh server crash hone ke bajaye 422 Unprocessable Entity return karta hai.
Topic 6: ML Testing & Mocking (FakeModel)

Examiner ka question: "test_api.py me FakeModel kyu use kiya gaya?"

Production CI/CD pipelines me real ML model load karne se tests bohot slow ho jate hain aur heavy GPU/RAM chahiye hota hai.
Humne FakeModel inject kiya jo model ke predict function ko simulate karta hai. Isse unit tests bina kisi MLflow server ya heavy model file ke 0.1 second me pass ho jaate hain.
Topic 7: Docker Containerization for MLOps

Examiner ka question: "Docker image me MLFLOW_TRACKING_URI environment variable kyu pass karte hain?"

Docker container isolated environment hota hai.
Jab container host machine ke MLflow server se communicate karta hai, toh hum environment variable pass karte hain: -e MLFLOW_TRACKING_URI=http://host.docker.internal:6001 Taaki containerized FastAPI app host machine par chal rahe MLflow Registry se @champion model download kar sake.

📌 Category 1: Model Monitoring & Drift (Assessment Ka Core)

Covariate Shift / Data Drift

Matlab: Input features ka distribution badal jana (jaise naye candidates ka average experience ya ratings badal jana).
Industry Tool: Evidently AI, Whylabs.

Concept Drift / Prior Probability Shift

Matlab: Input aur output ka relation badal jana (e.g., pehle jo resume score genuine tha, naye standards me wo inflated maana jana).

Drift Detection Statistical Tests

Matlab: Drift calculate karne ke statistical formulas.
Key Tests: KS-Test (Kolmogorov-Smirnov), PSI (Population Stability Index), Wasserstein Distance.

Data Degradation / Feature Drift

Matlab: Production me koi feature missing aane lagna, corrupt ho jana ya scale change ho jana.
📌 Category 2: Model Deployment & Serving Strategies

Champion-Challenger (Shadow / Dark Launching)

Matlab: Naya candidate model production me background me chalta hai (live predictions nahi deta), pehle uski accuracy compare ki jaati hai champion model se.

Canary Deployment

Matlab: Naye model ko 100% users ke liye release karne ke bajaye sirf 5% ya 10% users ko naye model ki predictions dena. Agar koi bug na aaye toh dheere-dheere 100% karna.

A/B Testing for ML Models

Matlab: 50% candidates ko Model A (purana) aur 50% ko Model B (naya) se evaluate karke business metrics compare karna.

Batch Serving vs Real-Time Serving

Batch: Roz raat ko 1 lakh resumes ek sath process karna (Cron job / Airflow).
Real-time: User ne website par form bhara aur turant 5 milliseconds me prediction aayi (FastAPI / REST API).
